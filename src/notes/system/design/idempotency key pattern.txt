Idempotency Key
    Unique value generated by the client (merchant server or app) sent with the request.
    It is a unique identifier for the intent.

    If server receives the same key, it won't process again, rather returning the original response from the first time.

    - The database should use a UNIQUE constraint for the key
    - A failed insert due to a duplicate value shows it already exists

Common patterns:
    - Request body fingerprinting
        Hash request body and store with the key.
        If the request body is different next time, error out to prevent key-reuse or bugs.
    - Expiration (TTL)
        Have these idempotency keys expire after a while when no longer relevant
    - Cache response only for non-retryable errors

This works with backpressure to ensure idempotency. With clients retrying continuously, this helps reduce work and double spend.

-> Often included as an HTTP header rather than in the request.
