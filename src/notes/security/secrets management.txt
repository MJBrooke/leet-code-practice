Centralised system for a dynamic, audited, centralised lifecycle of secrets

Lifecycle
    Generation: Cryptographically strong
    Storage: Encrypted at rest
    Distribution: Runtime injection (env vars or sidecars). Never on disk.
    Rotation: Regularly change keys
    Revocation: Ability to kill a secret across a fleet

Provides:
    - Access control: services can only find secrets relevant to them
    - Auditing: Logs who took keys when

Sidecar:
    - Sidecar authenticates itself
    - Fetches secret into shared memory volume
    - Application reads secret from file in memory
